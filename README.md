# TAMACODE plugin for Claude Code

**プログラムを知らない人でも Claude Code を安心して使えるようにする、日本語のプラグイン**です。

- **帯**: いま Claude が何をしているか、待っていていいかを入力欄の上に猫の顔文字つきで 1 行出す。あなたの番なら黄色
- **/tama**: 帯とペインをまとめて開く／もう一度で全部閉じる。起動時に自動で開く（`/tama auto off` で止められる）
- **操作盤（/panel）**: おねがい・ブラウザで見る・読む・戻す・おわり・点検・もっと簡単に・確認して をボタンで
- **見張り**: 秘密の鍵の直書きや `.env` のコミットなど「素人がやりがちな事故」を AI を使わずに止める／警告する（/tenken で全体点検）
- **自動バックアップ**: 大事な所を触る前に `.tama-backup/` に控えを取る
- **許可プロンプトの翻訳**: 「何をするか／消えて困るもの／危険度／おすすめ」の 4 行
- **エラー翻訳**: 1 行目は必ず「⚠ どこで」。Claude が直せる物は 1 行だけ、あなたの作業が必要な 4 種類だけ「あなたがやること」を出す。詳細は [+]
- **「たま」ペイン**: 用語（一言説明）／変更（やさしい 2 文の要約）／やったこと の 3 タブ
- **ひと区切り**: 返事が終わると「やったこと／確認の仕方／次にやること」の 3 行
- **迷走検知**: 同じファイルを読みすぎ・同じエラーを繰り返しているときに「迷ってるかも」
- **雰囲気モード（/kakkoii）**: 琥珀色の HUD（SESSION / TOKENS / FILES / EDITS / ERRORS と直近の道具のログ）と帯の進捗バー。数字は全部実データ
- Spinner（`Flowing…`）を実況に（猫 ＋ 動作 ＋ 対象 ＋ 目的 ＋ 経過時間）、完了行（`Crunched for 4s`）を「4秒で完了」に

> **注意**: この plugin の中心は Claude Code の **hooks module（function hooks）** という早期アクセス機能です。
> Claude Code **2.1.285 以前**では環境変数 `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` が必要です。**それ以降は不要**です。
> バージョンアップで API が変わり動かなくなる可能性があります。動作確認したバージョン: Claude Code 2.1.285（macOS）。

## インストール

```bash
git clone https://github.com/TAMAtechnics/tamacode.git
claude plugin marketplace add ./tamacode
claude plugin install tamacode@tamacode-marketplace
```

2.1.285 以前なら `~/.claude/settings.json` に次を足します（ユーザー単位なので、どのフォルダで起動しても効きます）。

```json
{ "env": { "CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1" } }
```

更新するときは、clone したフォルダで `git pull` してから `claude plugin update tamacode@tamacode-marketplace` → セッション内で `/reload-plugins` です。再起動は要りません。

## 文言とルールの差し替え

- 文言は `locales/ja.json`。`{name}` は差し込み。自分用の言い換えは `~/.claude/tamacode-ja.json` に置くとそちらが優先
- 見張りのルールは `rules/security.json`。自分用は `~/.claude/tamacode-rules.json`
- 雰囲気モードの設定は `config/vibe.json`。自分用は `~/.claude/tamacode-vibe.json`
- どれも起動時に読み込みます。初期値をコードにも焼き込みたいときは `node scripts/build-locale.mjs` / `build-rules.mjs` / `build-vibe.mjs`
- 用語辞書（`BUILTIN`）と道具の名前（`describeTool`）はコードの中です

## 帯: 今なにをしているか・待ってていいか

ツールが動くたびに、入力欄の上の帯に **1 行だけ上書き** で出ます。会話には残りません。

```
猫の顔 ＋ いま何をしているか（道具の名前は日本語、対象のファイルやコマンドつき）＋ 最後の動きからの時間 ＋ 待っていいかの一言
ヽ(=^･q･^=)ノ ビルド中: npm run build　最後の動き 1分5秒前　時間がかかる作業なので待ってOK
(=｡･q･｡=) 次の作業の準備中（LICENSE を作る手順を書いてます）　最後の動き 2秒前　書き出し中なので待ってOK
(=-q-=)zzZ 許可を待ってる: ファイルを削除してる: rm -rf dist　最後の動き 12秒前　あなたの番です。上を見て   ← 黄色
```

帯の時間は「最後に動きがあってから」です。Spinner の横の時間（ターン開始から）とは別物なので、固まっているかの判断は帯の数字で。

### Spinner（実況役）

帯は「待っていいか」の判定役、Spinner（オレンジの猫の横）は「いま何を・どうしてるか」の実況役です。形は **猫 ＋ 動作 ＋ 対象 ＋ 目的（分かる範囲で）＋ 経過時間（その動作が始まってから）**。

```
(=^･q･^=) hooks/activity.tsx を読んで、ロゴの描画位置を探してます（12s）
(=^･q･^=) 「NOTICE_REF」という言葉をプロジェクト内から探してます（3s）
ฅ(=^･q･^=)ฅ hooks/activity.tsx を書き換えてます（+14行）（40s）
ヽ(=^･q･^=)ノ figlet が入ってるか確認するコマンドを実行中（2s）
(=･q･=)? 次の手を考えてます。まだ何も触ってません（33s）
(=｡･q･｡=) 返事を書いてます（↓1.8k文字）（20s）
```

- **対象**は道具の引数から。ファイルはパスの末尾 2 階層。Bash は `description`（日本語の短い説明）があればそれを、無ければ先頭の動詞と対象を日本語に（`cat` → 中身を見る、`grep` → 探す、`npm run build` → ビルド、`git commit` → git にセーブ）
- **目的**は直前の Claude の発言の最後の文から 1 フレーズ。拾えなければ省略
- 端末幅に収まらなければ **目的 → 対象** の順に削ります。猫・動作・時間は必ず残ります
- 英語の道具名（Read / Edit / Bash）は出しません

| 状態 | いつ | 一言 |
| --- | --- | --- |
| A 実行中 | `tool.call` が来て結果がまだ | 時間がかかる作業（install / build / test / dev、WebFetch、サブエージェント、MCP）なら「待ってOK」。それ以外は一言なし |
| B 書き出し中 | モデルの文字が増えている（`turn.step`） | 「書き出し中なので待ってOK」。道具の指示を書いている間は「次の作業の準備中（対象）」 |
| C 返事待ち | 許可ダイアログや質問で止まっている | 帯が黄色になり「あなたの番です。上を見て」。下に許可の翻訳 4 行 |
| D 無反応 | A〜C のどれでもなく、最後の変化から 60 秒超 | 60 秒で「動いてないかも」、120 秒で「Escで止めて続きを頼むのが安全」 |

### 帯の下に出る物

- **【5】許可プロンプトの翻訳**: 「何をするか／消えて困るもの／危険度 低・中・高／おすすめ」。まず規則で即答し、裏で軽いモデル（haiku）が言い直す。危険度は規則の判定より下げない。高なら怒り顔 `(=｀･q･´=)ﾉ` と「分からなければNOで。あとで聞き直せます」
- **【4】エラー翻訳**: エラーかどうかは AI に任せず機械的に決めます（`hooks/errors.ts` の `isToolError`）。Bash は **終了コードが 0 以外**、または（cat / sed / grep / git log などの読むだけのコマンド以外で）出力に **Error / ERR! / failed / Traceback / EACCES / ENOENT / 401 / 403 / 500** を含むときだけ。表示が「…」で切れた正常な出力や、grep が何も見つからず終了コード 1 なのはエラー扱いしません。Bash 以外は道具が isError を返したときだけ。
  - 1 行目は必ず **「⚠ どこで」**: 失敗した道具と対象（`⚠ hooks/activity.tsx を書き換える処理が失敗`、`⚠ テストを実行するコマンドが失敗`）
  - **Claude が自分で直せる種類**（構文エラー・型エラー・テスト失敗・import 漏れ）は帯に 1 行「⚠ どこで。エラーが出ましたがClaudeが直してます」だけ。種類と生のエラーは [+] で開く。モデルには頼まない
  - **「あなたがやること」が出るのは 4 種類だけ**: ログインが必要 / API キーや .env が無い / 権限がない / 道具（node・git・brew など）が入ってない
  - それ以外は「⚠ どこで／何が起きた／Claudeが直せるか: たぶん直せる」の 3 行。「何が起きた」だけ裏で軽いモデルに言い直してもらう（失敗しても規則の行が残る）
  - 文は端末幅で切らず折り返す。3 行を超える分（生のエラーの見出し）は [+] で展開
  - 同じエラーが 3 回続いたら「同じ所で3回詰まってます。目的を言い直すか /onegai（おねがい）で整理」
- **【7】の知らせ**: 「(=｀･q･´=)ﾉ 大事な所を触ります。念のため控えを取りました（.tama-backup/…）」
- **見張り**: 止めた理由と代案とボタン、警告の赤い行
- **迷走検知**: 「(=´･q･`=) 迷ってるかも…」

### ひと区切りの 3 行まとめ

返事が終わると、完了行「(=^‥q‥^=)ﾉ 31秒で完了」の下に haiku が作った 3 行が出ます。

```
(=^‥q‥^=)ﾉ 31秒で完了
  やったこと: 猫の顔を足しました。
  確認の仕方: 入力欄の上の帯を見てください。
  次にやること: 特になし。満足なら終わりでOK
```

短い返事（40 字未満）や途中で止まった返事には付けません。

### 猫の顔

| 状態 | 顔 | 出る場面 |
| --- | --- | --- |
| 通常・待機 | `(=^･q･^=)` | 見出し、スキル |
| 読んでる | `(=^･q･^=)` | Read、Bash の cat / head / sed、Grep / Glob、git の状態 |
| 書いてる | `ฅ(=^･q･^=)ฅ` | Edit / Write、道具の指示を書いている間 |
| 考え中 | `(=･q･=)?` | Spinner の考え中、次を考えている間、計画 |
| ネット検索 | `(=^･q･^=)ゞ` | WebFetch / WebSearch / curl / MCP / 外部サービスの CLI、サーバー起動中 |
| コマンド実行 | `ヽ(=^･q･^=)ノ` | Bash（ビルド・テスト・インストールなど）、サブエージェント |
| 完了 | `(=^‥q‥^=)ﾉ` | 完了行、戻した、ブラウザで開いた、点検で異常なし |
| ひと区切り | `(=｡･q･｡=)` | 返事を書いている間、TodoWrite、「終わってから送ります」 |
| エラー | `(=T_q_T=)` | 道具がエラーで終わった、無反応 60 秒 |
| 迷ってる | `(=´･q･`=)` | 迷走検知 |
| 危ない操作 | `(=｀･q･´=)ﾉ` | rm / git push / reset --hard、控えを取った、見張りの警告、変更タブの危険マーク、危険度 高 |
| 止めた | `(=｀q´=)つ` | 道具が拒否された、見張りが止めた、無反応 120 秒 |
| 寝てる・待ち | `(=-q-=)zzZ` | 許可待ち、質問待ち、空のペイン、作業中で押せない |

## 「たま」ペインと /tama

右側に出るペインは 1 枚で、**操作盤／用語／変更／読む／おねがい／戻す／点検／履歴** のタブがあります。`/tama` で帯をオンにしてこのペインを開き、もう一度 `/tama` で全部閉じます（帯もオフ。見張りが止めた知らせだけは出ます）。端末が 110 桁未満、またはペインが 44 桁未満のときは **タブを隠して操作盤だけ** 出します。起動時に自動で開くかは `/tama auto on|off`（既定オン、`$.store` に保存）。

## 操作盤と 8 つの機能

操作盤タブには全部の機能がボタンで並びます。Claude の作業中はボタンが消え「終わってから押してください」と出ます。入力途中・履歴・結果は `$.state` と `$.store` に残り、再起動しても消えません。

### 【1】おねがいウィザード（/onegai）

「何を作りたい？」「どの画面・機能で？」「どうなれば成功？」の 3 つを埋めて「送る」。
`【やりたいこと】…【場所】…【成功の条件】… まず計画を3行で出して、私がOKと言ってから作業して。終わったら確認の仕方を3行で。` が送られます。1 つでも空なら送らず、赤く「ここを埋めてください」。直近 5 件の依頼は履歴から押して欄に戻せます。

### 【2】もっと簡単に（/kantan）

「今の説明を小学生にも分かる言い方で言い直して。長さは半分に。専門用語は使わない。」を送ります。用語タブの上にもボタンがあります。

### 【3】読む（/yomu）

直近に Read / Edit したファイル 10 件がボタンで並び、押すと「○○を、プログラムを知らない人向けに段落ごとに日本語で説明して…」を送ります。返事は「読む」タブに残り、押すと開けます。

### 【6】戻すのプレビュー（/modosu）

git の履歴 10 件と控え（`.tama-backup`）が選択肢に並びます。選ぶと先に「ここに戻すと消えるもの」を 3 行（差分を haiku に要約させる。失敗したら変わるファイル名）。「戻す」を押したときだけ実行し、直前に `git stash` で今の状態を控えます。実行は `git restore --source=<時点> --staged --worktree -- .`（履歴は消さない）か、控えのファイルの書き戻しです。

### 【7】危険操作の前に自動バックアップ

Edit / Write / MultiEdit / NotebookEdit / Bash の前に、対象が「削除・データベース・認証・支払い・.env・rm・git push --force・migration」に当たるか判定します。当たったら、ファイルは `.tama-backup/<日時>/<相対パス>` にコピー、Bash は `git stash create` → `git stash store` でスナップショット。`.gitignore` に `.tama-backup/` を足し、7 日より古い控えは最初の道具のときに消します。見張りの警告で通したときも控えを取ります（止めたときは取りません）。

### 【8】おわり（/owari）

「今日の作業を『やったこと／途中のもの／次回の最初の一手』で docs/作業日誌.md に日付付きで追記して、日本語メッセージでコミットして、次回用の依頼文の下書きを1つ作って docs/次回.md に置いて。」を送り、返事が終わると帯が「(=^‥q‥^=)ﾉ 今日はここまで。次回は docs/次回.md から」になります。

### 確認して（/kakunin）

「ビルド（組み立て）とテスト（動作の自動確認）を回して、合格か不合格かと、不合格なら原因を一言で教えて。」を送ります。

### ブラウザで見る（/miru）

localhost・ポート・開発サーバーを知らなくても「作ったものを見る」ができます。

1. よくあるポート（3000 / 5173 / 4321 …、`package.json` と `.env` の PORT から見当）に `curl` で当たり、動いていればブラウザで開く
2. 動いていなければ `package.json` の `dev` / `start` を Bash 道具（裏で実行）で起動し、立ち上がり（最長 90 秒）を待って開く
3. 起動方法が分からなければ Claude に「開発サーバーを起動して…」と頼む文を送る

動いている間は画面下の状態行に **「🟢 サーバー起動中 localhost:3000」** が光り続け（10 秒ごとに確認）、操作盤にも緑の行が出ます。Claude が自分で `npm run dev` を打ったときも光ります。

## 雰囲気モード（/kakkoii）

`/kakkoii` でオン・オフ（`$.store` に残る）。やさしい日本語の帯は常にそのままで、次が足されます。

- **HUD ペイン**（右側、等幅・琥珀色の単色・細い罫線）。上段は SESSION（セッションの経過時間）／TOKENS（入出力トークンの累計。キャッシュ分も入力に含む）／FILES（読んだファイル数、重複なし）／EDITS（編集回数）／ERRORS（失敗した道具の数）。1 秒ごとに更新。下段は直近の道具呼び出しのファイルパスとコマンド（新しいものが上、既定 10 行）
- **帯の進捗バー** `[████░░░░]`。書き出し中はこのターンの出力トークン（既定 200 トークンで 1 マス）、道具の実行中は経過秒（既定 10 秒で 1 マス）。横に実数（`412 tok` / `25s`）
- **ハッカー風の行**（全部実データ）: `CTX [███░░░░░]  38%`（文脈の窓の使用率。`$.session.usage()` から）、`OUT/30s ▁▂▃▅▇…`（直近 12 分を 30 秒ごとに区切った出力トークン量のスパークライン）、道具が動いている間だけ `▶ RUNNING  bash  00:12`（1 秒ごとに ▶ ▷ が交互。書き出し中は `WRITING  claude`）
- **起動演出**（オンのときだけ）: ASCII ロゴ（TAMACODE の右に大きい猫）→ 「TAMACODE SYSTEM ONLINE」→ 前回の `docs/次回.md` の 1 行目 を 1 秒間隔で帯に
- **Desktop アプリ**では HUD を SVG で描き、トークンの棒は前回の値からなめらかに動きます（数字そのものは文字）。ターミナルでは文字で描きます
- 数字はすべて実データ。トークンは `turn.step` の stop と `turn.complete` の usage から数え、二重に足しません。見せかけの％やダミーはありません

## 見張り（AI 不使用。パターン照合だけ）

判定ルールは `rules/security.json`。`.env.example`、`tests/`、`docs/`、`node_modules/`、`.tama-backup/` は対象外。「直して」を押したときだけ Claude が修正作業をします。

### 【1】止める（道具を拒否し、帯に理由と代案とボタン）

| 何を | 文言とボタン |
| --- | --- |
| Edit / Write の内容に API キーらしい文字列（`sk-` `AKIA` `ghp_` `eyJ…` や 32 文字以上のランダム英数字。`process.env` の行は除く） | 「秘密の鍵がコードに入りそうです。.env に入れて process.env で読む形にします？」[はい] [このまま通す] [やめる] |
| `git add` / `commit` / `push` の対象に `.env` `.env.*`（`.env.example` は除く）`*.pem` `*.key` `credentials.json` | 「秘密のファイルが一緒に入ります。外して続けます？」[外す] [やめる] |
| `service_role` が `app/` `components/` `pages/` `public/` 配下に書かれる | 「これは管理者用の強い鍵で、画面側に置くと誰でも使えます。サーバー側だけで使う形に直します？」[直す] |
| `gh repo create --public` や公開先の追加 | 「全世界に公開されます。社内のコードなら private にしてください」[privateにする] [公開でいい] |
| 本番（`.env.production` / `--prod` / 本番プロジェクト ID）に対する drop / delete / reset / truncate / rm -rf | 「本番のデータを消す操作です。開発環境で試してからにしてください」[やめる] |

[はい]／[直す] は Claude に修正を頼む文を送ります（作業中なら終わってから）。[このまま通す] はその操作を 1 回だけ通し、Claude にやり直しを頼みます。

### 【2】警告（通すが帯に赤。同じ箇所は 1 回だけ）

- `supabase/migrations` に `create table` があり、同じテーブルに `enable row level security` が無い →「このテーブルは誰でも全部見える状態です（RLS＝自分の分しか見えない決まり が無い）」
- `app/api/**/route.ts` または `"use server"` のファイルに auth・getUser・getSession・session のどれも無い →「この入口は本人確認なしで誰でも叩けます」
- パスに `admin` を含むページ／ルートに認証判定が無い →「管理画面が無防備です」
- `console.log` / `logger` に email・phone・address・password・token を含む変数 →「ログに個人情報が出ます」
- `npm install` / `pnpm add` / `yarn add` の後に `npm audit --json` を回し、high 以上があれば「入れた部品に既知の穴があります」

### 【3】点検（/tenken）

押したときだけプロジェクト全体をスキャンします（最大 400 ファイル、1 ファイル 200KB まで）。上の全項目に加えて、`git log -p`（直近 200 コミット）に鍵らしい文字列が無いか、`.gitignore` に `.env` が入っているかを見ます。結果は「赤（止めるべき）／黄（直した方がいい）／緑（OK）」で一覧になり、各行に [直して]（Claude に修正を頼む文を送る）と [大丈夫]（次から出さない）。冒頭に「今週止めた事故：3件　警告：n件」。緑だけなら「(=^‥q‥^=)ﾉ 素人がやりがちな事故は見当たりません」。

## 用語・変更・履歴のタブ

`/terms` `/changes` `/log` はそれぞれのタブを選んで「たま」ペインを開くコマンドです。

### 変更タブ（/changes）

Edit / Write / MultiEdit ごとに「時刻・ファイル名・やさしい日本語 2 文の要約・＋n行 −n行」。要約は **20 行以上の変更のときだけ** 軽いモデル（haiku）に頼み、それ未満は「ファイル名＋±行数」だけ。削除・データベース・認証・支払い・`.env`・`rm` に関わる変更は行頭に `(=｀･q･´=)ﾉ`、末尾に「※壊れると困る所です。不安なら戻してと言ってください」。押すと元の差分が開きます。履歴は 50 件、再起動後も残ります。

### 用語タブ（/terms）

Claude の返事とツールのエラー出力から、辞書にある専門用語を拾って一言説明を並べます。1 語 1 行で説明は折りたたみ（「説明を開く」で全部開く）。**語を押すと「知ってる」** になって次から出ません。＊はツールの出力から、†は自分の辞書。新しい語が上。

| コマンド | 働き |
| --- | --- |
| `/terms add 用語 説明` | 自分の辞書に足す（`用語: 説明` でも可） |
| `/terms rm 用語` | 自分の辞書から消す |
| `/terms know 用語` / `/terms unknow 用語` | もう出さない／また出す |
| `/terms list` / `/terms file` | 自分の辞書の一覧／ファイルの場所（`~/.claude/tamacode-terms.json`） |

### 履歴タブ（/log）

帯に出た一言の履歴（新しい順、最大 200 件）。同じことが続いたら「×3」にまとまります。エラー・拒否・許可待ちも残ります。

## 迷走検知

ひとつの返事の中で、同じファイルを **5 回以上** 読んだ（Read だけでなく Bash の cat / head / sed も数える）か、同じエラーが **3 回以上** 続いたら、帯に「(=´･q･`=) 迷ってるかも。目的をもう一度言い直すか、/plan で整理すると抜けやすいです」と出し、最初の 1 回だけトーストも出します。次に話しかけると消えます。

## hooks module を増やすときの決まり

- `hooks.json` の `modules` に書けるのはプラグインにつき 1 つ。機能を増やすときは `hooks/<機能>.tsx` を作って `hooks/tamacode.tsx` から `register` を呼ぶ
- マッチャー無しの同じイベントは module 全体で 1 回しか登録できない。`session.start` は `changes.tsx`、`tool.call` / `turn.start` / `turn.complete` / `turn.step` / `classic.PermissionRequest` は `activity.tsx` が持つ。2 つ目からはマッチャー付きで
- ペインの描画（`ui.render` の `requestId: "tama"`）は `panel.tsx` の 1 か所。タブを増やすときはそこに分岐を足す
- `$` を別ファイルの関数に渡すと `claude plugin validate` に拒否される。`$` を使う処理は同じファイルの中で書き、別ファイルからは純粋な関数だけを import する（`watch.ts` `permission.ts` `errors.ts` `server.ts` がその例）
- `$.state.get` / `$.env.get` の参照や名前はリテラルで書く（変数で渡すと拒否される）
- `$.command.run` で自分のプラグインのコマンドを呼んでも、自分のフックは飛ばされて届かない
- `command.run` の中から `$.prompt.submit` は呼べない（そのコマンドが持つターンを待ってしまう）。`$.clock.after(0, …)` で次の瞬間に送る
- ● ○ † のような「曖昧幅」の記号は画面によって隣の字に重なるので、UI の印は ASCII（[ ] * +）か絵文字（幅 2 で安定）にする
- フックが返った後の裏処理は `$.clock.after(0, …)` で別の dispatch に載せる（そうしないと途中で打ち切られうる）
- JSON は import できない。`locales/ja.json` と `rules/security.json` は起動時に `$.fs.read` で読み、初期値は生成した `.ts` に焼き込む

### 検証とテスト

```bash
claude plugin validate ./.claude-plugin/plugin.json   # マニフェスト・型契約・hooks module を検証
claude plugin test .                                   # hooks/*.test.tsx と tests/*.test.tsx を実行
bunx tsc -p tsconfig.json                               # 型チェック（下の「型チェックを通すには」）
```

`.claude-plugin/` には marketplace.json もあるため、`claude plugin validate .` はマーケットプレイス側だけを見ます。プラグイン本体は `plugin.json` のパスを渡してください。

## 開発中に試す

```bash
claude --plugin-dir ./tamacode
```

この起動方法だと編集のたびに自動で再読み込みされます。インストール済みの方と二重に読まれるのを避けるため、`/plugin` から tamacode を一時的に無効にするか `claude plugin uninstall tamacode@tamacode-marketplace` で外してください。

## 型チェックを通すには

`.claude-plugin/types/` は Claude Code が生成する型定義の置き場で、リポジトリには入っていません。Claude Code のセッション内で `/plugin-types .claude-plugin/types` を実行すると生成され、`bunx tsc -p tsconfig.json`（または `npx -p typescript tsc`）が通るようになります。
